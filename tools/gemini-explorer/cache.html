Context Caching

Cache large content once, then query it repeatedly without re-sending tokens. Save cost and latency on repetitive tasks.

How it works: Context caching lets you upload a large body of text (a book, codebase, transcript, etc.) to the Gemini API once as a "cached content" object. You then reference that cache by name in subsequent requests — the model reads from the cache instead of re-processing the same tokens every time. This means faster responses and lower costs for repeated queries against the same content. The cache has a TTL (time to live) — it auto-expires after that duration.

Response

Your API key is saved in your browser's session storage — shared across all Gemini Explorer pages, but automatically cleared when you close the tab. It is only sent directly to the Google Gemini API. Cached content is stored server-side by Google and auto-expires after the TTL you set. Learn more about context caching.
